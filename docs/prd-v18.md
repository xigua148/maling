## 0. 一句话背景

v1.7.3 底座已把「连续性」立住：记忆中心五分区（偏好 / 话题 / 情绪 / 往期回顾 / 她的日记）、emotions 历史上限 200 条（`_EMOTIONS_HISTORY_MAX`）、意图五态路由、反馈三键、每周回顾、主动连续性全部在跑。但她的"认知"仍是**扁平的**：她知道"主人喜欢 Rust"，却不知道"小李是主人的同事、上周离职了、主人心情不好和这事有关"；她记着 200 条情绪，却从未把这些点连成**一条弧线**给主人看；她陪了你几个月，却没有一张"我们一起经历过什么"的地图。

v1.8 一句话：**把扁平记忆升级为结构化认知——关系网络（谁在你生命里）、情绪弧线（你的高低起伏）、共同经历时间线（你们的来路），再配上场景感知（她知道你此刻在哪种状态里）、回应规则（你定的约定她永远守）、影像记忆（你分享过的图她记得）**。群聊与 Pi 引擎 v1.7 已定形，本期不碰。

## 1. 增量范围

### 1.1 P0（认知深化三件套——"她真的认识我"核心）

- **F1 记忆图谱 / 关系网络**：MemoryManager 增**人物实体**存储（名字 / 关系类型 [同事/朋友/家人…] / 备注 / 相关事件）——记忆中心可视化关系卡片；LLM 注入按相关实体带上下文（"小李是主人的同事，上周离职了"——事件因果级理解）。数据落 `user_memory.json` 顶层 `entities` 键（PM 定口径，见 §4.1）。
- **F2 情绪弧线**：基于 emotions 历史（200 条）跨会话情绪追踪——记忆中心弧线视图（**R-A 红线：档位色块 / 表情呈现，绝不报数字**）+ LLM 查询支持（"我最近状态怎么样" → 注入情绪概览档位描述）。
- **F3 共同经历时间线**：highlights（`query_range` 已有，highlights.py:160）+ 话题归档 / 纪念日事件 → 时间线视图（记忆中心分区，按月分组）——"我们一起经历过…"的载体。纯规则汇总零 LLM。

### 1.2 P1（体验与个性化 + 多模态）

- **F4 场景化陪伴**：场景 = 工作 / 休息 / 睡前 / 自定义（可增）——自动感知（**时段为主**，简化不加应用前台检测）+ 手动切换；每场景一套 system 语气指令注入（**走 request_injections 既有基建**，chat_service.py:1123 先例 NIGHT_CARE_INJECTION）；主动行为随场景（工作模式减少主动打扰）；与意图五态 / 情绪陪伴模式的关系 = **三层叠加、优先级分层**（口径见 §5.1）。
- **F5 角色卡分享标准**：v1.7 导入导出已有——正式格式规范文档（版本标记 / 字段标准 / 兼容性声明）+ 导入预览增强（v1.7.x 遗留项收编：字段逐项预览 / 冲突提示）+ 可选卡面封面字段。
- **F6 自定义回应规则**：用户设"当我说 XX 时你要 YY"——结构化规则存储（触发词 / 回应风格）+ **命中触发词当轮注入**（request_injections 基建，零常驻 token 成本）+ 记忆中心管理页（增删改查）；与偏好 / 抑制表的关系口径见 §5.3。
- **F7 多模态记忆**：用户分享过的图片她"记得"——看图会话的**对话摘要存入记忆**（默认零成本档，PM 定口径见 §5.4），聊天中可召回（"上次发的那张截图"）；识别失败 / 无视觉模型的诚实边界（绝不假装记得）。

### 1.3 明确不进 v1.8（Non-goals）

- **不做语音通话闭环**（延续 prd-v14 起边界）。
- **不做桌宠深化**（MaidPet 保持现状）。
- **不做 AI 生成插图 / AI 生成形象**（形象资产继续走本地 PNG 管线，F7 只"记住"图片、绝不"生成"图片）。
- **不做回忆相册**（图片墙 / 相册式浏览明确排除——F7 的影像记忆是"认知原料"不是"相册产品"，只服务对话召回与记忆中心条目，不做独立图片浏览面）。
- **不碰群聊与 Pi 引擎**（v1.7 已定形：群聊自由发言调度、Pi 内置，本期零改动）。
- 不做知识图谱推理 / 实体关系自动推演（"小李的老婆是谁"类多跳推理不在本期——F1 只做"存储 + 相关注入 + 展示"三层，推理留给 LLM 自然语言能力本身）。
- 不做情绪数据的跨设备同步 / 云端分析（R-I）。

## 4. P0 详细设计

### 4.1 F1 · 记忆图谱 / 关系网络

**用户故事**：作为主人，我的生活里有一群重要的人——同事小李、发小小雅、我妈。我希望码铃知道他们是谁、和我什么关系、发生了什么；我提到"小李"时她能接得住上下文，而不是每次都要从头介绍。**她认识我身边的人，才算真的认识我。**

**现状确认（代码核实）**：
- `memory.py` **无任何 entities 雏形**（全文件 grep 无命中）——人物实体为全新增。
- v1.6 D-V16-01 确立了顶层新键扩展模式：`_merge_defaults` 读时迁移、meta.version 不升、旧文件零破坏——F1 沿用。
- LLM 注入入口 = `build_memory_context(max_chars=300)`（偏好全量 + 活跃话题 3 条）——实体注入在此扩展。
- 记忆中心 page_memory_book.py 已是 **5 Tab**（主人偏好 / 活跃话题 / 情绪记录 / 往期回顾 / 她的日记）——新分区归属见 Q-D2。

**数据口径裁决（PM 定）**：**落 `user_memory.json` 顶层 `entities` 键**，不建独立 entities.json。
- 理由：①与 emotions 先例同模式，`_merge_defaults` 读时迁移零成本；②LLM 注入已在 MemoryManager，实体注入同源最顺；③记忆中心页已持有 memory_mgr 引用，UI 直连；④单一数据文件与"删除即遗忘"链（refresh_system_context）天然复用。
- **结构**：`entities: [{id, name, relation, notes, events: [{date, text}], pinned, created_at, updated_at, source}]`——relation ∈ 同事/朋友/家人/恋人/同学/其他（开放枚举可自定义）；events 按时间倒序、每实体上限 20 条；实体总数上限 100（超出提示整理，不自动淘汰——人物记忆不应悄悄消失）；source ∈ manual / assistant_proposed（女仆提议后用户确认）。

**交互草案（文字描述）**：
- **记忆中心新分区「人物关系 👥」**：关系卡片网格（名字 + 关系标签 + 最近一条事件摘要 + 最近提及相对时间）；点开卡片 = 实体详情（备注可编辑 + 事件列表可增删）；「➕ 添加人物」手动录入；每张卡可置顶（pinned）/ 删除（确认框，物理删除立即生效）。
- **录入的"提议-确认"模式（亮点，LLM 辅助提取默认关，Q-D1）**：开启后，对话命中关系句式（"我同事/我朋友/我妈/我们领导…" + 人名）时，女仆在回复尾部轻问一句"要不要我把小李记进你的人物卡片？📝"（附 [记下来] [不用了] 两键，复用反馈三键组件样式）；确认后写入（source=assistant_proposed）+ `intent_notice` 小字确认。**绝不静默写入**——人物记忆必须经主人确认（R-I 精神：关于"你身边的人"的记忆，比偏好更敏感）。
- **LLM 注入（按相关实体）**：`build_memory_context` 扩展——本轮用户消息**命中实体名**（精确匹配 name，含 pinned 实体始终注入）→ 追加该实体行"【关于小李】同事；备注：…；最近：上周离职了（9-03）"。注入上限 2 个实体 + pinned 1 个，实体段与既有偏好/话题共享 300 字符预算（超限按 pinned > 命中 > 事件新近排序裁剪）。
- **红线自检**：无"人脉统计"、无关系数值、无亲疏排序。

**数据 / 接口依赖**：
- `memory.py`：`_DEFAULT_MEMORY` 增 `entities: []`；新增 `add_entity / update_entity / delete_entity / add_entity_event / list_entities / find_entities_by_name(text)`（命中查询供注入用）；`build_memory_context` 扩展实体段（签名不变，D-V16-03 微调先例）。
- `session.py`：删除/修改后 `refresh_system_context()`（既有，零新增）。
- `gui/pages/page_memory_book.py`：新分区 Tab（Q-D2 定归属）；实体卡片组件。
- `gui/chat_service.py`：提议-确认两键挂接（复用 proactive_feedback 组件样式，v1.6 D-V16-05 先例）；提议默认关配置键 `entity_auto_propose`（默认 False）。

**验收标准**：
1. 实体增删改查全链路落盘 `user_memory.json`；删除实体后当轮 `build_memory_context()` 不再包含（refresh 断言）；旧文件（无 entities 键）加载零破坏。
2. 对话提及"小李" → 该轮请求 system 含小李实体行（pinned 实体始终注入）；未提及 → 零实体注入（零 token 无关，零 prompt 污染）。
3. 提议-确认模式默认关；开启后未经确认绝无静默写入（自动化断言：无确认路径不调 add_entity）。
4. 上限护栏：实体 >100 / 事件 >20 时写入被拒并友好提示；不自动淘汰。
5. 红线扫描零命中；深色模式 + theme_color 全覆盖。

**风险与工作量**：**中风险**（新数据面 + LLM 提取提议链是新增交互模式）。2.5–3.5 人日（schema+注入 0.5–1d + UI 1–1.5d + 提议链 1d）。**优先级理由**：P0 头部——"认识你身边的人"是"她真的认识我"的最强信号；事件因果注入（"上周离职了"）是 v1.6 扁平记忆做不到的认知跃迁。

### 4.2 F2 · 情绪弧线

**用户故事**：作为主人，我想偶尔看看"我最近的状态"——不是冷冰冰的统计数字，而是一条温柔的弧线：哪段时间元气满满、哪几天有点低落、低落时她陪我说了什么。看懂自己，也是一种被陪伴。

**现状确认（代码核实）**：
- `memory.py` emotions 历史**已有**：`_EMOTIONS_HISTORY_MAX = 200`（:41）、append 淘汰（:455-462）、`get_emotions_history()` 只读接口（:481-483）——数据侧零新增。
- 情绪四类（tired/happy/anxious/lonely）+ 记忆中心"情绪记录"Tab 已有时间倒序列表——F2 是把**点连成线**。
- **缺口**：无聚合视图、无 LLM 查询通道（用户问"我最近怎么样"时模型手上没有情绪概览原料）。

**交互草案（文字描述）**：
- **弧线视图（记忆中心「情绪记录」Tab 顶部新增区块）**：按周一行的**日格色带**——最近 8 周 × 7 天，每格按当日主导情绪着档位色（平稳=主题淡色 / 元气=暖黄 / 有点累=淡橙 / 低落=淡蓝——色值走 theme_color 语义扩展，深浅色模式各配）；当日多条记录取出现最多者，无记录 = 空格（浅灰点，不臆造）。**hover 显示档位词**（"那天有点累"），**全程无数字**（R-A：无日期悬停计数、无情绪次数统计行）。
- **今日格**：最新一格带轻呼吸动画（v1.6 handsfree 呼吸动画先例），点击跳到该日情绪条目列表。
- **LLM 查询支持**：用户问"我最近状态怎么样 / 我最近是不是很丧"（intent 五态 emotion 命中或显式疑问句式）→ 该轮 request_injections 注入**情绪概览段**：近 7 天与近 30 天各一句档位描述（"最近一周多数时候平稳，有两天显得疲惫；上个月整体元气多一些"——纯规则模板生成，**零 LLM 调用、零数字**）+ 女仆可自然接话。查询开关：总开关默认开（概览注入 ≤80 字符，成本可忽略）。
- **红线自检**：无情绪分数 / 无百分比 / 无"低落 N 天"计数 / 无趋势箭头打分；弧线是"给你看"不是"给你评"——页面固定一行说明："这只是帮你看见自己，不是给你打分。"

**数据 / 接口依赖**：

### 5.1 F4 · 场景化陪伴

**用户故事**：作为主人，上班时我希望她安静专业、别频繁打断我；睡前我希望她声音放轻、聊聊舒缓的；休息时她可以活泼一点。**同一个她，不同时刻刚刚好的陪伴。**

**现状确认（代码核实）**：
- request_injections 基建已有：chat_service.py:1123 请求级注入列表 + NIGHT_CARE_INJECTION 深夜关切先例（:67、:1137，仅 chat 态、非 Agent 生效）——场景语气注入直接挂此位。
- 主动行为侧：ProactivePolicy 四重闸 + v1.6 D-V16-11 `external_cooldown_until` 外部冷却输入先例——场景降低主动打扰沿用"入闸加输入"模式。
- 意图五态（intent.py）、情绪陪伴模式（v1.7 F6 安慰模式）均在跑。

**场景与既有机制的关系裁决（PM 定，三层叠加、优先级分层）**：

| 层 | 维度 | 优先级 | 说明 |
|---|---|---|---|
| ① 情绪陪伴模式 | 情绪维度（主人低落） | **最高**（临时覆盖） | 激活期间场景语气注入**暂停**（避免双重指令打架）；退出后场景恢复 |
| ② 场景 | 时段维度（现在什么状态） | 中（会话底色） | 进入场景时注入该场景 system 语气指令（会话级一次，非每轮） |
| ③ 意图五态 | 单轮消息维度（这句话是什么） | 最细（单轮附加） | 与场景正交叠加（场景管基调、五态管这轮怎么接） |

- **冲突规则**：①>②：情绪模式激活 → 场景注入挂起；②>③：场景只改基调不改路由（五态附加行为不受场景影响——工作场景下"提醒我"照样写入待办）。
- **场景切换的注入实现**：切场景时下一条消息起生效（system 语气指令随请求注入一次）；会话中途切换 → 复用 v1.5.1 角色切换边界 system 消息模式（幂等边界消息"场景切换：语气转入工作模式"）。

**交互草案（文字描述）**：
- **场景定义（内置四场景，自定义可增，Q-D4）**：
  - 💼 工作：语气简洁专业少撒娇、动作描写减半；**主动打扰降档**（主动问候单日上限 3→1，Q-D6 定口径）；回复避免长篇闲聊收尾。
  - ☕ 休息：默认基调（无人设改动，即 v1.7.3 现状）。
  - 🌙 睡前：语气放缓放轻、多陪伴式回应、少技术反问（与深夜关切 NIGHT_CARE_INJECTION 语义合并——22:30 后自动进入，避免双注入）。

### 5.3 F6 · 自定义回应规则

**用户故事**：作为主人，有些约定我想一劳永逸——"当我说'今天好累'别给我建议，陪我就好""当我发'上线了'你就说辛苦了"。**她守约的样子，就是可靠的模样。**

**现状确认（代码核实）**：
- request_injections 基建已有（chat_service.py:1123，请求级、不入历史）——规则注入直接复用。
- 记忆中心页已有分区框架与增删改交互模式——规则管理页照搬交互。
- **缺口**：无任何"用户显式指令"结构化存储；偏好（她自动记的）与用户约定（用户定的）混在同层。

**与偏好 / 抑制表的关系裁决（PM 定）**：
- **偏好** = 她自动记的画像（source=auto 为主，被动沉淀）；**回应规则** = 用户显式定的约定（manual，主动指令）——**规则命中时优先于偏好**（约定 > 画像）。
- **抑制表**（v1.6"先不提"mute）= 负向策略（她不主动提什么）；**回应规则** = 正向回应（她该怎么接话）——两者正交：规则不受 mute 影响（用户主动设的约定不该被历史反馈覆盖），mute 也不清规则。

**交互草案（文字描述）**：
- **设置方式（双入口）**：①聊天中直接说（"以后我说上线了你就说辛苦了" → intent 五态路由或句式命中 → 女仆复述确认 + [记下约定] [算了] 两键——提议-确认模式，与 F1 同款组件）；②记忆中心「回应约定 📌」分区手动增删改查。
- **规则结构**：`{id, trigger, response, enabled, created_at, source}`——trigger = 触发词/短语（≤20 字）；response = 期望回应描述（≤100 字，描述风格或具体话术均可）；单用户上限 **20 条**（Q-D9，防 system 污染与维护负担）。
- **注入机制（命中当轮注入，零常驻 token）**：每轮用户消息与 trigger 做包含匹配（精确子串，不做模糊语义）→ 命中 1–3 条 → request_injections 追加"【回应约定】主人说过：当他说「上线了」时，请回应…"；未命中 → 零注入零成本。**Agent 模式跳过**（与场景/深夜关切同边界）。
- **呈现**：命中时 `intent_notice` 小字"📌 已按你的约定回应"；规则列表每条带启用开关 / 上次命中时间（相对时间，无命中计数——R-A）。
- **红线自检**：规则不是"驯化成就"（无"你们已有 N 条默契"）、无规则使用率排行。

**数据 / 接口依赖**：
- `memory.py`：顶层新键 `response_rules: []`（`_merge_defaults` 迁移模式）；`add_rule / update_rule / delete_rule / match_rules(text)`。
- `gui/chat_service.py`：match_rules 挂 request_injections（在场景/情绪注入之后的注入序位）；提议-确认两键复用。
- `gui/pages/page_memory_book.py`：新分区 Tab。

**验收标准**：
1. 设"当我说上线了你要说辛苦了" → 下次说"上线了" → 回复遵守约定（抽样评审 ≥3 规则）；未命中规则的轮次请求零注入（payload 断言）。
2. 规则增删改查 + 启用开关即时生效；删除后当轮不再注入（refresh 断言）。
3. 上限 20 条写入被拒有提示；提议-确认模式无确认不落盘（断言）。
4. 规则命中与偏好注入、mute 策略互不干扰（三方可并存断言）；R-A 扫描零命中。

**风险与工作量**：低。1–1.5 人日。**优先级理由**：P1——"守约"是人设可信度的最后一公里，且技术全为既有基建的复用（注入位 / 确认组件 / 分区框架），性价比极高。

### 5.4 F7 · 多模态记忆

**用户故事**：作为主人，我上周发过一张报错截图给她，今天想问"上次那个报错后来怎么样了"——我希望她记得那张图、记得当时的对话，而不是一脸茫然。**她看过的，就是她经历的。**

**现状确认（代码核实）**：
- 看图链：`_image_attachments_to_data_uris`（chat_service.py:1785）——图片 data URI **当轮直传、不落盘、不回溯历史、不存任何记忆**；`vision` 标记（:1927）供错误提示；Agent 模式忽略图片（:1861）。
- **无"识别结果"结构化对象**——模型对图的描述自然融在 assistant 回复文本里，无独立抽取点。
- R-I 现状：图片帧/URI 当轮内存即弃——F7 必须延续"原图永不落盘"。

**成本档裁决（PM 定，默认零成本档）**：
- **默认档（零额外 LLM 调用）**：带图消息发送成功后，自动存一条**影像记忆**：`{time, user_text（用户配文 ≤50 字）, assistant_digest（她当时回应的首段摘要 ≤50 字，截断自已有文本）, image_note（"用户分享了一张图片"中性描述）}`——**绝不存原图 / data URI / 缩略图**（R-I 硬线）。这记录的是"你们分享过什么"的**对话事实**，不是图像识别结果——诚实且零成本。
- **增强档（可选开关，默认关，Q-D8）**：视觉模型可用时，对图片追加一次轻量结构化识别调用（max_tokens=120："用一句话描述这张图的关键内容"）→ 结果存 `image_note`（替代中性描述）；成本 ≈ 每图一次 1k token 内。失败静默回落默认档。
- **召回**：用户消息命中"上次/之前 + 图/截图/照片"句式（规则）→ 检索影像记忆（关键词重叠 + 时间倒序 top2）→ request_injections 注入"【之前的分享】9-03 主人发过一张图（配文：xxx），当时码铃回应：…"；命中时 `intent_notice` 小字提示。
- **诚实边界（R-K 核心验收）**：①发送当时模型**不支持视觉** → 不存影像记忆（她没看过就是没看过），且用户日后问起 → 诚实回应"那次发送时码铃没能看到图"；②识别失败的增强档 → image_note 保留中性描述，**绝不编造图像内容**；③影像记忆条目在记忆中心可查看可删除（沿用删除即遗忘链）。

**交互草案（文字描述）**：
- 影像记忆的查看入口：记忆中心「情绪记录」旁不新增独立分区（Non-goals 排除相册）——**并入既有分区作为条目类型**（"情绪记录"或"往期回顾"Tab 内以卡片类型区分，Q-D2 一并拍板）或最小方案：仅在召回注入 + 记忆中心列表体现，无专属图片化 UI。
- 带图消息发送成功 → `intent_notice` 小字"🖼 这次的分享码铃记在心里了"（一次性轻提示，可关）。

**数据 / 接口依赖**：
- `memory.py`：顶层新键 `vision_memories: []`（上限 50 条滚动淘汰）；`add_vision_memory / query_vision_memories(keyword) / delete_vision_memory`。
- `gui/chat_service.py`：发送成功路径（`_on_stream_finished` 附近）存档钩子（`vision` 标记已有，判断就绪）；召回注入挂 request_injections；增强档识别调用（开关 `vision_memory_enhance` 默认 False）。
- `page_memory_book.py`：影像记忆条目渲染（文字卡，无缩略图）。

**验收标准**：
1. 带图成功发送 → 影像记忆落盘且**不含任何图像二进制 / data URI**（文件内容断言，R-I 硬线）；纯文本消息零写入。
2. 问"上次发的那张截图" → 回复引用影像记忆内容（抽样 ≥3 用例）；无匹配 → 诚实说"没找到那次分享"，不编造。
3. 无视觉模型时发送图片 → 不落影像记忆；日后问起 → 诚实边界话术（断言）。
4. 增强档默认关 = 零额外调用；开启后失败静默回落、绝不编造图像描述。
5. 删除条目当轮生效；50 条滚动淘汰；既有看图链零回归。

**风险与工作量**：**中风险**（召回命中率的规则长尾 + 诚实边界的测试面）。1.5–2 人日。**优先级理由**：P1 收尾——多模态认知是"她经历过的"叙事延伸，默认零成本档把成本与隐私风险都锁死在下限；列 P1 末位因其依赖召回体验的打磨迭代。
