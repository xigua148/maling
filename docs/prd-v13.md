## 0. 一句话背景

v1.2 让码铃「住在桌面里」：有房间、有心情、有角落宠物、她会先开口。
v1.3 是陪伴体验的**第二英里**——她要能**听见主人说话、开口回复、看得懂主人屏幕、任何时候一按就出现、离开时被惦记、回来时被迎接**。全部 11 项已由用户拍板**全量实现**，不做选择题；本文档负责把边界、红线、落点、打包代价写清楚，供架构排期。

## 1. 增量范围（v1.3 只做这些）

### 1.1 S 级（P0 · 必须交付）
1. **TTS 语音输出**——女仆回复可朗读；聊天内「朗读本条」按钮 + 设置开关（`README.md` 需同步）。
2. **区域截图直接问**——全局热键划屏截图 → 以图片发给码铃 → 走 v1.2.2 看图链路回答（已有看图链路，只缺截图入口）。
3. **全局唤起热键**——任意界面呼出/隐藏主窗，默认 `Ctrl+Alt+M`，可配置。
4. **「等她回来」Idle 问候**——键盘/鼠标**全局空闲**检测 → 用户恢复操作时问候一句。

### 1.2 A 级（P1 · 目标范围内应交付）
5. **女仆小游戏**——抛硬币 / 抽签 / 猜拳 / 21 点；她当荷官。
6. **免提语音对话模式**——连续「你说她说」，免持开关，复用现语音链路。
7. **高光回忆册**——收藏高光对话，独立「回忆」页（参考 prd-v12 A7 足迹设计，**不做打卡/断签**）。
8. **托盘右键完整菜单**——显示/隐藏、📷 拍照、🎤 语音、截图提问、设置、退出。

### 1.3 B 级（P2 · 全部实现，排期靠后）
9. **开机自启**——设置开关、**默认关闭**，实现走 HKCU Run 或 startup 目录，可干净移除。
10. **日历/纪念日**——记住生日 / 首次相见日，当天一句主动祝福（走 A9 有节制调度 + 免打扰 + 频控；只做温暖仪式，**绝不做倒数日/断签/打卡焦虑**）。
11. **深色模式跟随系统**——现有 3 主题基础上加「跟随系统」开关，Windows 深浅色检测，扩展 `theme_engine.py`，**不硬编码颜色**。

### 1.4 明确不进 v1.3（用户已裁决搁置）
- 节日限定皮肤 / 节日限定对话（用户原话「到时候再说」）。本 PRD 不为其预留承诺，仅资产与主题层保持可扩展位（新增色键走取色器体系，天然可扩展）。

## 2. 铁律红线区（v1.3 总体约束，跨需求强制）

> 承接 prd-v12 §8 与 design-v12「总体约束」，并针对 v1.3 新域做延伸。**实现与验收逐条对照，归零才放行。**

| # | 红线 | v1.3 强制口径 |
|---|---|---|
| R-A | **无焦虑红线延续（全 UI）** | 全 UI 不得出现心情值/好感分数/经验条/token/货币/筹码/胜率/连胜/进度条/断签/倒计时等养成数值。小游戏、回忆册、纪念日尤其注意（各条细口径见需求说明）。 |
| R-B | **不做监督/评判式陪伴** | 摄像头/麦克风**永不做**学习监督、在场感知、专注度分析、内容分析。Idle 问候只能走**系统级键盘/鼠标空闲检测**（如 `GetLastInputInfo`，仅取「距上次输入毫秒数」，不读取任何按键/鼠标内容）；免提语音仅在**用户显式开启**时采集，用途 = 转成对话文字，绝不旁路分析。 |
| R-C | **不做打扰式推送** | 所有「码铃主动开口」（Idle 问候、纪念日祝福、A9 既有三类）一律走 A9 有节制调度口径：应用运行期、免打扰时段（22:30–08:00）外、冷却 + 单日上限。不做 24h 后台常驻说话、不做系统级定时弹窗/闹钟。热键/截图/呼出是**用户主动动作**，不属推送。 |
| R-D | **只增量不重构** | 不碰 GUI 三栏主窗骨架；不重构会话/消息数据模型；不重构 ChatService 用户发送链路（主动消息沿用 `proactive_ask()` 独立入口，见 design-v12 §3.10）；尽量不动已交付链路。托盘升级为「共用图标」属增量迁移，若迁移成本评估为重构级则退回最小形态（见 P2-4 说明）。 |
| R-E | **数据纯本地** | 陪伴/回忆/纪念日数据存 `~/.maid_coder/`（companion.json 扩展或独立 json）；功能开关走 `config.yaml`（AppConfig）或 `gui/config.py`（GuiConfig）；绝不上云。TTS 若引入联网后端，须单独明确标注并**默认关闭**（见 P1-1）。 |
| R-F | **打包友好** | 新增依赖逐个列明 exe 体积 / 离线性 / spec hiddenimports 影响（见 §6）。优先零第三方依赖实现（ctypes/winreg/Qt 自带），可选项不阻塞默认产物。 |

## 3. 需求池

优先级口径沿用 prd-v12：
- **P0** = v1.3 必须交付（S 级 4 项）；**P1** = 目标范围内应交付（A 级 4 项）；**P2** = 明确有价值、v1.3 排期靠后（B 级 3 项，**仍在 v1.3 承诺内**，非延后版本）。

> ID 说明：**ID 前缀 P1./P2. 表示开发批次**（P1 批 = S 级先行；P2 批 = A+B 级），**与「优先级列」的 P0/P1/P2 是两套维度**，请勿混读。批次建议详见 §7 裁剪建议。

### 3.3 P2 批 · B 级（优先级 P2，仍在 v1.3 承诺内）

## 7. 待确认问题（收敛 + 默认建议）

> 状态：以下为 v1.3 **产品级开放项**，均已给默认建议；默认建议未经架构反驳即按此执行，正式裁决结论落 design-v13（若架构文档同批次产出）或本节补记。

1. **Q1 · 主窗 X 关闭行为（P1-3/P2-4 前置）**
   现状：主窗关闭即退出、托盘仅挂独立聊天窗。热键「呼出/隐藏主窗」与托盘「显示/隐藏」都要求**主窗可常驻隐藏**。
   **默认建议**：主窗 X = 最小化到托盘（应用继续驻留）；「❌ 退出」只走托盘菜单；设置「通用」区提供「关闭窗口时直接退出」开关（默认不勾）。属行为变更，不重构骨架，需实现改动 `main_window.closeEvent`。
2. **Q2 · TTS 后端范围**
   用户要求评估 edge-tts 或 SAPI。edge-tts 音质好但联网 + 文本上云（触碰 R-E）；SAPI5 离线但音色朴素、依赖系统中文语音包。
   **默认建议**：v1.3 只交付 **SAPI5 离线默认实现**（R-E 最稳、零体积），`gui/tts.py` 抽象后端接口；edge-tts 高质量女声列为 **v1.3 后续可选**（默认关 + 隐私明示）。若产品坚持 v1.3 就出女声音质，则 edge-tts 升为默认并接受「需联网、发送待朗读文本」的明示提示——请架构给出成本后再决。
3. **Q3 · Idle 问候阈值与 A9 关系**
   **默认建议**：系统 Idle 问候阈值独立配置默认 30 分钟（短于 A9 app 内 90min）；触发**并入 proactive gates 且共享 cooldown**——同一冷却窗口内 A9 app 内问候与 Idle 问候不双发；当日计入同一 daily_cap（防打扰最大化）。若产品希望 Idle 问候是「她一直等着」高频陪伴，可给独立 cap=2，需显式决策（默认共享）。
4. **Q4 · 截图提问发送时机**
   **默认建议**：选区完成 → 进附件条 + 预填一句引导文案，**不自动发送**（用户确认/改字后发送）；避免误发浪费 token 与截图被误用。视觉模型缺失时沿用既有报错引导。
5. **Q5 · 小游戏数值边界（后台也不加分？）**
   pet_click 计分键已有 30 分钟冷却先例。小游戏若不接后台好感分，则「羁绊随游戏增长」不存在，仅情绪/文案联动。
   **默认建议**：**小游戏不新增 intimacy 计分键、后台也不加分**（彻底去养成化，符合 R-A）；仅冷却外的「game」事件做一次情绪反馈（happy/surprised 短暂表情 + 台词），30 分钟内只回普通台词。
6. **Q6 · 回忆收藏范围**
   **默认建议**：AI 与用户气泡均可收藏（用户自己的名场面/需求记录同样值得收藏）；收藏快照含会话引用便于回溯定位。
7. **Q7 · 免提退出方式**
   **默认建议**：三通道——界面「⏹ 停止」按钮、说关键词「暂停/结束对话」（前端识别固定词）、任意系统输入打断（灵敏度待真机调）。免提期间自动暂停 A9 主动消息。
8. **Q8 · 纪念日祝福配额**
   **默认建议**：纪念日祝福**独立 1 次/日配额，不占 A9 日常 3 条 cap**（温暖仪式不被日常问候挤掉）；仍受 quiet 免打扰约束；错过不补发。
9. **Q9 · 深色模式切换范围与资产（v1.3a 修订：接受架构 D-V13-09 范围收窄）**
   **默认建议**：v1.3 深色 = 色板级（`colors_dark` 变量替换），**范围收窄为「主要表面 + 文本可读」最小目标面**（主窗背景 / 聊天消息区 / 输入区 / 设置页 / 侧栏主表面 + 正文对比度可读）；既有内联 setStyleSheet 硬编码浅色（chat_window / message_bubble / sidebar 的 `#FFF8FA` / `#FFE4EC` 等）**仅替换其中支撑最小目标面的一小部分到语义键，不做全量清扫**（全量硬编码清扫 = 一次重构级 sweep，违反 R-D，列 v1.3 后 P2+ 续做）；不做插画/图标的深色重绘（P2 口）；主形象/宠物用柔化圆形容器垫底防穿帮；托盘 ico 深色变体不承诺。验收口径以 design-v13 的「深色覆盖清单」为准（清单内取色正确 + 无新增硬编码 + 文字可读；清单外允许过渡但不得刺眼白块）。
