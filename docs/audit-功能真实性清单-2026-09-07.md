## 一、审计方法与判定口径

**源码态（source）**：以受管 Python 真实 import + 真实调用验证（文件操作走临时目录、网络为真实网络请求、剪贴板为真实系统剪贴板；GUI 相关用 offscreen Qt 冒烟）。**exe 态（dist_v148f）**：以 `_internal` 目录内容 + 构建产物（PYZ/toc 侧证）核对二进制依赖是否随包。

| 判定 | 含义 |
|---|---|
| ✅ 可用 | 源码态实测通过，入口→实现链路完整 |
| 🔗 依赖断链 | 实现真实，但所依赖的第三方库在源码环境/exe 中缺失，必挂或降级 |
| 🌏 选型不可达 | 实现真实，但依赖的外部服务在国内网络不可达，永远失败 |
| 🫥 空壳 | 后端实现真实，但 GUI 无任何入口（只有 CLI/隐藏路径能触达） |
| ⚠️ 待实测 | 结构真实，但受环境限制（无麦克风/无 API key/REPL 交互）本轮未能端到端验证 |

**测试环境**：Windows 11 沙箱（无麦克风、无摄像头）；网络基线对照：duckduckgo.com / google.com 6s 内 ReadTimeout，baidu.com 200 OK。

## 四、Top 修复建议（按优先级）

**P0-1｜web_search 国产化改造（用户点名，影响最大）** — 1–2d
① 引擎替换：ddgs → 国内可达源（博查 API / 百度智能云 / Bing CN），保留 ddgs 作海外回退；② GUI 补入口：聊天页加"联网搜索"开关或工具按钮（当前 GUI 普通聊天 0 入口，只有 CLI 隐藏逻辑和 Agent 模式工具两条窄路）；③ 超时从默认值收紧到 6–8s 并给"网络不可达"的明确反馈，避免用户感知为"点了没反应"。

**P0-2｜psutil 依赖修复** — 0.5h
requirements.txt + 打包 spec 补 psutil；或在 agent_tools.py:617/722 增加 stdlib 降级（无 psutil 时用 tasklist/wmic）。当前 exe 里 `list_processes` 必挂、`system_info` 缺内存/CPU 数据。

**P1-1｜file_move 白名单预检参数 bug** — 0.5h
agent_tools.py:57 `args.get("path") or args.get("filepath")` 增加 `src`/`dst` 取值（或按 tool_name 映射参数名）。现状：白名单内路径的 file_move 也走授权弹窗，安全预检形同虚设（功能不灭，属安全/体验缺陷）。

**P1-2｜知识库 / 待办 GUI 入口补齐** — 0.5–1d
两者后端均实测可用却 GUI 零引用——正是用户"光有入口没有作用"的镜像问题（反着：有能力没入口）。建议：工具箱页（page_toolbox.py）加"知识库"面板；首页/聊天侧栏加待办卡。各 0.5d 内。

**P2｜待实测清单真机回填** — 0.5h
麦克风（D9）、摄像头（D12）、看屏端到端（D10）、CLI REPL（E1）、exe 开机自启（D3）——全部为环境受限而非代码疑点，真机各花几分钟即可销项。

## 五、结论

用户"很多功能光有入口没有作用"的反馈**部分成立**：
- **web search 确实"永远失败"**，但根因是 🌏 选型（ddgs 国内不可达）+ GUI 无入口双重问题，**不是**"exe 没打 ddgs"（已证伪，ddgs 在 PYZ 内、primp 也在）；
- 真正"有实现无入口"的空壳是**知识库**与**待办**两项；
- 必挂级断链仅 **psutil** 一处；其余 33 项功能链路真实可用，5 项受沙箱环境限制待真机销项。
