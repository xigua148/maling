## 1. 增量范围（三大块）

### 1.1 A 块 · 4 套 UI 风格全实装 + 切换器（本期最大批）

- **四风格**（视觉稿为设计基准，色值见 §4.1）：
  - **A 现代极简**：浅色留白 / 圆角卡片 / 克制线条，玫红点缀（`--bg #F7F7F8 / --accent #E0457B / radius 14px`）。
  - **B 温暖奶油**：奶油暖底 / 柔粉 / 大圆角软阴影（`--bg #FFF8F3 / --accent #FF8FA3 / radius 20px`）。
  - **C 深色夜间**：深底高对比 / 玫光点缀（`--bg #131114 / --accent #FF6B9D / radius 14px`）。
  - **D 鲸鱼娘深海清爽**：深海蓝 + 鲸鱼青 + 浅海渐变 + 气泡鲸鱼点缀（`--bg #EEF6FA / --accent #2E9BB5 / radius 18px`）；该风格下**品牌文案随鲸鱼娘人设**（范围见 §4.3）。
- **切换**：设置页「界面风格」下拉 + 聊天页顶栏快捷入口；**即时生效无需重启**；持久化 GuiConfig。
- **与现有主题引擎的关系**：全站统一重做，但**不破坏**既有强调色派生机制（`_custom_accent`）/ 浅深模式（`colors_dark` + `set_theme_mode`）/ `theme_changed` 单参信号契约。落法口径见 §4.2（含旧配置读时映射）。

### 1.2 B 块 · 字体系统

- **内置 2 款（OFL 1.1，可随包）**：
  - **资源圆体 Resource Han Rounded**——正文/UI 默认；子集化 **6763 常用字**（GB2312 全集 + ASCII + 中文标点），**Regular + Medium 两字重 ≈ 4–5 MB**。
  - **jf open 粉圆 Open Huninn**——标题/点缀；子集后 ≈ 数百 KB，**严禁用于正文**（简体覆盖仅 69%，调研报告 §2.1）。
- **保留 4 款系统字体**（幼圆 / 雅黑 / 楷体 / 等线）作可选；**雅黑作生僻字 fallback 保底**（家族链 `资源圆体子集, Microsoft YaHei, sans-serif`）。
- **字体切换器**（设置页下拉）+ 持久化；`QFontDatabase.addApplicationFont` 注册 + `applicationFontFamilies` 取**真实 family name**（不凭文件名猜）。
- 随包附 **OFL 许可副本与版权声明**；子集化脚本（pyftsubset / fonttools）在**构建流程固化**（新增依赖仅构建期用，不进运行时与 exe）。

### 1.3 C 块 · 人设「名字 / 自称 / 称呼」规则

- **核心规则**：**名字与人设标签分离**——现 `name` 字段存的是人设标签（"温柔女仆 / 猫娘"），**不得作为自称**；新增独立「名字」字段。
- **自称规则**：有名字 → 自称**名字**；无名字 → 自称**"我"**（绝不用人设标签自称）。
- **7 套预设命名（用户已定）**：①温柔女仆 →「小铃」②鲸鱼娘 →「**小鲸**」+ 称呼主人「**小鱼干**」或「主人」（语境自然切换）③猫娘 →「小咪」④雌小鬼 →「铃奈」⑤温柔姐姐 / ⑥毒舌博士 / ⑦编程老手 → **不配名字（自称"我"）**。
- **鲸鱼娘角色设定补全（用户认可，联网查证社区梗）**：傲娇 + 懒 + 聪明、服从主人、**绝对拒绝被叫胖（被叫胖会炸毛回怼）**、白米饭执念、摸鱼 / 找外包梗；自称"小鲸"；语气参考视觉稿（"哼，记下了…小鲸…"）。
- **清理"自称女仆"残留**：13 处已排查（清单见 §6.2），按新规则全部修正。
- **授权提醒（硬约束）**：鲸鱼娘形象源于社区二创（原作者「溟月」，CC BY-NC-SA 4.0 非商用）→ 码铃**只用现有 `preset_whale` 资产与自创名「小鲸」**，**不得直接使用"溟月"名或搬运二创图**。

### 1.4 明确不进 v1.9（Non-goals）

- **不改女仆形象资产**（`gui/assets/maid/` 表情差分与形象 PNG 零改动——A 块只改 UI 壳层，不重绘角色）。
- 不做语音通话闭环 / 桌宠深化 / 回忆相册（**列 v2.0 候选**）。
- **不动 Pi 引擎与群聊**（v1.7.x 已定形，本期零触碰）。
- 不新增功能面（v1.9 是纯视觉与人设层版本，聊天 / 记忆 / 陪伴行为逻辑零改动）。
- 不做动态主题（随时间自动换色）/ 壁纸自定义 / UI 缩放（DPI 适配沿用既有行为）。
- 不内置第三款字体、不引入 B/C 级授权字体（R-L）。

## 4. A 块详细设计：4 套 UI 风格全实装 + 切换器

### 4.1 用户故事与四风格定义

**用户故事**：作为主人，我希望码铃看起来像 2026 年的精致应用，而不是字形老旧的工具——白天我想要清爽留白，晚上想要护眼的深色，心情好时想要暖乎乎的奶油感，而如果我用的是鲸鱼娘，整界面都该是她的深海色。

**四风格设计基准（视觉稿色值，实施以视觉稿为准）**：

| 风格 | 设计定位 | 核心色（视觉稿 :root 变量） | 圆角 | 语气关键词 |
|---|---|---|---|---|
| A 现代极简 | 浅色克制、内容优先 | bg `#F7F7F8` / surface `#FFF` / border `#EBEBEF` / text `#1C1C1E` / accent `#E0457B` / accent-soft `#FCEEF4` | 14px | 干净、留白、玫红点睛 |
| B 温暖奶油 | 暖底柔粉、亲和包裹 | bg `#FFF8F3` / surface2 `#FFFBF8` / border `#F5E6DC` / text `#3D2E2A` / accent `#FF8FA3` / shadow `rgba(255,143,163,.13)` | 20px | 奶油、软阴影、圆润 |
| C 深色夜间 | 深底高对比、夜间护眼 | bg `#131114` / surface `#1C1920` / border `#2C2733` / text `#F2EFF5` / accent `#FF6B9D` | 14px | 深邃、玫光、沉静 |
| D 鲸鱼娘深海 | 深海蓝 + 鲸鱼青 + 浅海渐变 | bg `#EEF6FA` / surface2 `#F4FAFC` / border `#D5E8F0` / text `#12303F` / accent `#2E9BB5` / accent-soft `#E0F2F7` | 18px | 清爽、气泡、深海 |

**验收标准**：
1. 四风格在主窗 / 浮窗 / 设置页 / 记忆中心 8 Tab / 首页 / 角色页 / 对话框全量覆盖——无"漏改页"（逐页截图核对表，清单随验证文档留档）。
2. 每风格 × 浅深模式（适用者）渲染无裸色、无错位；视觉稿组件形态（卡片 / 气泡 / 按钮 / 输入区）与实现一致（设计基准逐项对照）。
3. 切换即时生效（<200ms，无重启、无闪烁、无残留旧色）；重启后保持。
4. 强调色盘（v1.4.3 既有）在四风格下均可派生自定义强调色并即时生效；恢复默认回到该风格默认强调色。
5. 红线扫描零命中（四风格 × 全部页面）。

### 4.2 与现有主题引擎的关系（落法口径）

- **增量方式**：`THEME_DEFINITIONS` 新增四风格条目（键建议 `ui_minimal / ui_cream / ui_night / ui_whale`），每风格提供完整 `colors` + Layout token；**浅深模式机制保留**——A/B/D 三风格各自再提供 `colors_dark`（视觉稿未含深色态的，由设计在实施期补，作为架构/设计交付项）；C 深色夜间风格见 Q-E2。
- **旧配置读时映射（老用户零失效）**：既有 `GuiConfig.theme` 值 `cute / minimal / maid` 读时映射到新风格（建议 `minimal→ui_minimal`、`maid→ui_cream`、`cute→ui_cream`）——见 Q-E1；映射只做读取兼容，**不删旧 QSS 文件**（R-D）。
- **强调色派生不破**：`_custom_accent` + `_active_palette` 运行时 merge 机制零改动；新风格只需注册强调色语义键（`focus_accent / accent_light / text_on_accent` 等既有键位）。
- **QSS 组织**：沿用 `base.qss`（公共结构层）+ 风格 QSS（肤感层）双层机制；四风格 QSS 为**新写**（视觉稿还原），base 层按需增量补组件选择器，不动已有变量替换逻辑。
- **切换器落点**：设置页「外观主题」区扩为「界面风格」（下拉 + 三个预览色块）；聊天页顶栏加风格快捷入口（图标点击弹出小菜单，四项）；切换走既有 `load_theme`（新增一档 `ui_style` 配置键，或复用 `theme` 键——见 Q-E1）。

**风险与工作量**：**高风险**（全站 QSS 重做 = 最大回归面；多人汇交点 main_window/sidebar/chat_panel/各页面）。4–6 人日（四风格 QSS 还原 3–4d + 引擎增量与映射 0.5d + 切换器 0.5d + 全站截图回归 1–1.5d）。**优先级理由**：用户点名的第一诉求（"现在字形偏旧、不够精致"）；四风格是品牌门面，也是 D 鲸鱼娘风格（C 块人设的视觉延伸）的载体。

## 5. B 块详细设计：字体系统

### 5.1 用户故事

**用户故事**：作为主人，我希望界面上的字又圆又精致、粗细有层次，而不是一整套幼圆的单薄感；但我也不想因为换了字体，遇到生僻字变成方块。

### 5.2 落法

- **内置字体清单**：
  - 资源圆体 Regular + Medium（正文 / UI 默认；子集 6763 字 ≈ 4–5 MB 合计）；
  - jf open 粉圆（标题 / 点缀；子集 ≈ 数百 KB；**严禁正文**——简体覆盖 69%）；
  - 保留系统可选：幼圆 / 雅黑 / 楷体 / 等线。
- **注册与解析**：新 `gui/fonts.py`——`resolve_font_path()`（`_MEIPASS` / `_internal/fonts/` 双路径）+ `register_bundled_fonts()`（`addApplicationFont` + `applicationFontFamilies(fontId)[0]` 取真实 family）+ `font_family_chain(choice)`（返回家族链字符串）。
- **接入点（一处改动）**：`theme_engine.load_theme` 中 `${font_family}` 的替换值改为读用户字体设置（风格仅提供"推荐默认"）；`app.setFont(QFont(family, 10))` 同理取链首 family。
- **fallback 链**：内置圆体链 = `"<资源圆体真实 family>, Microsoft YaHei, sans-serif"`；子集外字符由 Qt 字形回退到雅黑——**验证含生僻字（如"龘"）不显示方块**。
- **子集化与打包**：
  - 新增构建脚本 `tools/build_fonts.py`（pyftsubset，字表 = GB2312 6763 + ASCII + 中文标点；**仅构建期依赖 fonttools，不进 requirements 运行时、不进 exe**）；
  - 产物落 `gui/assets/fonts/`，spec `datas` 收集进 `_internal/fonts/`；
  - 随包附 OFL 许可副本（`docs/third_party_licenses/`）+ About 页「开源组件」字体条目 + 保留名称规则核对（R-L）。
- **切换器**：设置页「外观 → 字体」下拉（选项：资源圆体（默认）/ jf open 粉圆（仅标题）/ 幼圆 / 雅黑 / 楷体 / 等线）+ 持久化 GuiConfig `font_family`；即时生效（重新应用 setFont + 触发 QSS 重建）。

**验收标准**：
1. 默认字体 = 资源圆体（Regular 正文 / Medium 强调），界面字重层次可辨；重启保持用户选择。
2. 粉圆**不出现在正文字体选项**（或标注"仅标题"且代码侧禁设为正文——见 Q-E4）；标题位（首页大标题 / 页头）在选用粉圆时生效。

**用户故事**：作为主人，我不希望她张口就说"女仆这就去办"——她该有自己的名字（小铃、小鲸），或者坦然说"我"。名字是她的，人设标签（"温柔女仆""猫娘"）只是告诉别人她是哪一类的，不该拿来当她自己的名。

## 7. 与既有红线映射 / 澄清（防团队误读）

| 问法 | 澄清 |
|---|---|
| 「四风格全站重做算不算违反 R-D 只增量？」 | 不违反。R-D 禁的是**推翻既有机制**：主题引擎的变量替换 / 浅深模式 / 强调色派生 / 信号契约**全部保留**，四风格是 `THEME_DEFINITIONS` 的**增量条目 + 新增 QSS 文件**，旧三主题 QSS 文件保留、旧配置读时映射。这是"加四套新皮肤"，不是"拆引擎重写"。 |
| 「C 深色夜间风格和已有'外观模式深色'是不是重复？」 | 二者维度不同：外观模式是**明暗维度**（浅/深/跟随系统），风格是**设计语言维度**（极简/奶油/夜间/深海）。C 风格的特殊性在于它**本身就是深色设计语言**——两者关系口径见 Q-E2（建议 C 下强制深色、模式选择器收起）。 |
| 「D 鲸鱼娘风格文案随人设，会不会把产品名也改了？」 | 建议只改**界面自称类文案**（状态提示 / 欢迎语 / 自称），窗口标题与关于页的**产品名"码铃"保持不变**（产品名不随皮肤变，否则用户找不到应用）——Q-E3 确认范围。 |
| 「内置字体是不是又引入第三方依赖？」 | 字体是**数据文件**（随包 assets），不是 Python 依赖；fonttools 仅在**构建期**用于子集化，**不进 requirements 运行时、不进 exe**（R-D/R-F 精神）。授权走 R-L（OFL 白名单 + 许可副本）。 |
| 「清理'自称女仆'会不会破坏温柔女仆人设？」 | 不会——"女仆"作为**角色类别/人设标签**继续存在（角色卡仍叫"温柔女仆"），只是**不再进自称位**（改自称"小铃"）。这是"名实分离"，不是去女仆化。 |
| 「子集化后用户打出生僻字怎么办？」 | R-L ④ 硬约束：家族链 fallback 到雅黑，Qt 自动字形回退；验收 3 专项测生僻字 + emoji + 文件名三类文本源，绝不出现方块。 |

## 9. 分批建议（供架构参考）

> team-lead 已定方向：**C（独立小批）→ B（字体系统）→ A（4 套 UI，最大批）**。以下为依赖细化与理由：

1. **第一批 · C 块（1–1.5d）**：零依赖、独立可交付、快速见效（用户核心诉求"自称有人味"）；且 C 块的命名规则是 **D 风格"文案随人设"的依赖项**（先有名字规则，D 风格文案才有正确的自称来源）。
2. **第二批 · B 块（1.5–2.5d）**：字体是四风格的**共同底座**——先换字体，四风格的效果评估才准确（幼圆单薄会掩盖风格差异）；同时构建脚本 + 许可合规是纯增量、风险窄。
3. **第三批 · A 块（4–6d，最大批）**：四风格 QSS 全量还原 + 全站截图回归。建议：①先做 A/B/D 三风格（浅色系）+ C 风格（深色）分两小轮；②每完成一风格即跑一次全站截图清单；③强调色盘与浅深模式在四风格下的组合回归（v1.4.3 先例：30 组合遍历）。
4. **资源收缩裁剪顺序**（从下往上砍）：A 块的 D 鲸鱼娘风格（可 v1.9.x 补）→ B 块的粉圆点缀字体（资源圆体必保）→ A 块四风格降为两风格（A 极简 + B 奶油）→ 系统字体项保留即可。**C 块与 B 块资源圆体不裁**（成本最低、收益最直接）。
