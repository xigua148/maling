## 二、P0 —— 收益明确、建议优先做

### 1. 设置页投影「只挂 1/12」，视觉不一致（试点未收口）
- **证据**：设置页共 **12 个分区**（`_create_section` 调用：`page_settings.py:109/280/291/361/432/492/542/583/626/674/761` + `:801` 更新区），
  但只有「外观与效果」一个挂了投影 —— `page_settings.py:113` `elevation.apply_card_shadow(theme_frame, ...)`。
- **影响**：用户滚设置页会看到「只有第一块有阴影」，观感割裂。这是 v2.1 质感试点②明确的未收口项。
- **建议**：把 `apply_card_shadow` 下沉到 `_create_section()`（`page_settings.py:780`）里统一挂，一处改动覆盖全部 12 个分区。
- **成本/风险**：低。已有 `ENABLED` 总开关可一键 A/B；注意换肤时 `refresh_all` 要能覆盖新挂载点。

### 2. `chat_panel.py` 3926 行 —— 超大模块需拆分
- **证据**：`gui/widgets/chat_panel.py` 3926 行，是全项目最大模块；次大 `gui/chat_service.py` 2634、`page_settings.py` 2298、`page_role.py` 2123。
- **影响**：单聊/群聊/流式渲染/表情剥离/头像全挤在一个文件，改一处风险外溢；也是此前「头像不切换」「标记泄漏」两个 bug 的同一出险区。
- **建议**：按职责拆出「消息渲染」「会话状态」「输入区」三个子模块，先做纯移动、不改行为，配回归测试保底。
- **成本/风险**：中（改动面大），但可分批；**建议先补测试再拆**。

### 3. 1033 处宽泛 except —— 错误被大面积静默吞掉
- **证据**：`gui` + `core` 中 `except:` / `except Exception` 共 **1033 处**。
- **影响**：真实异常被吞，问题只能靠用户肉眼反馈（本项目已多次因此「用户先发现、我们后知」）。
- **建议**：不必全改；优先收敛**静默 pass** 的那些（只 `pass` 或只 `log.debug`），改为至少 `logger.warning` 带上下文；给核心链路（聊天、会话存档、更新）加窄异常。
- **成本/风险**：低-中，可增量做。

## 三、P1 —— 值得做，需评估

### 4. 按压反馈只覆盖侧栏，可铺开
- **证据**：全应用仅 1 处挂载 —— `gui/main_window.py:429` `transitions.install_press_feedback_recursive(self.sidebar)`；`QPushButton` 出现 325 处 / 89 文件。
- **建议**：优先铺 QToolButton 与主要对话框按钮；`QListWidget`（侧栏导航项）需 viewport 事件过滤，成本高，单独评估。
- **风险**：与已装的 `QGraphicsOpacityEffect` 互斥类问题需留意（一个 widget 只能装一个 effect）。

### 5. `setStyleSheet` 228 处 —— 重绘与维护双重成本
- **证据**：228 处 / 89 文件。
- **影响**：主题切换时需全量刷新；局部 QSS 覆盖应用级 QSS，是此前「某些页文字没颜色」类问题的结构成因。
- **建议**：收敛为「应用级 QSS + 少量主题变量」，减少逐控件 setStyleSheet；三页 `_apply_theme()` 已有兜底，可继续推广该模式。

### 6. 死代码 / 双源主题定义
- **证据**：`role_avatar_changed` 为死信号（0 emit 点）；`_UI_THEMES` 与 `THEME_DEFINITIONS` 并存，后者含 3 个旧兼容主题（hint 对比度仅 ~2.0–2.2，不达标）。
- **建议**：删死信号；评估旧兼容主题能否下线，否则至少禁止新增代码引用 `THEME_DEFINITIONS`。

### 7. 启动链路：网络检查 + 后台线程
- **证据**：`gui/main.py:1098` 创建 `UpdateChecker`；`:497` 启动日记补写 `threading.Thread`。
- **建议**：更新检查改为「启动后延后 N 秒 + 非阻塞」；确认各后台线程 daemon 化、退出时可 join。

## 四、P2 —— 长期 / 体量大

### 8. 包体积：Pi 运行时 226 MB
- **证据**：`_internal/pi_runtime` 226 MB / 13,567 文件，占整包绝大部分（onedir 327MB、onefile 222MB）。
- **建议**：评估「首次使用时按需下载」或精简 node_modules（去除 dev 依赖/文档/测试文件），可显著缩小分发体积。

### 9. 测试 flaky：整跑段错误 EXIT=139
- **证据**：曾在 `tests/test_v21_settings.py` 处 Qt 拆卸竞态崩溃，单独跑通过、重跑也通过 → 竞态型 flaky。
- **建议**：隔离 Qt 拆卸顺序，或给该文件加独立进程运行（pytest-forked 类方案，注意不引入新依赖红线）。

### 10. 日志规范：10 处裸 `print()`
- **建议**：统一走 `logger`，便于落盘与分级。

## 五、已知性能风险（来自 v2.1 实测，供参考）

- 投影边际 **≈0.18 ms / 卡 / 次重绘**；消息气泡视口 8–12 个时每帧 +1.4–2.1 ms（占 60fps 预算 8–13%）。
- **内存是真风险**：每个 `QGraphicsDropShadowEffect` 持有一张离屏位图，长会话累积 100–300 张，随会话增长。
  → 若要把投影铺到气泡/列表动态项，必须先解决「仅视口内挂载 + 上限」与内存回收。
