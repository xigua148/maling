## 0. 一句话背景

v1.5.2 底座已夯实，但"陪伴"有三个断层：**她记的东西你看不见**（MemoryManager 跑了一年零透出面，情绪记录只存单条）；**她主动开口说完就断**（build_topic_followup 已实现但全树无调用方，你的回应影响不了她下次说什么）；**对话细节有毛边**（失败即丢、停止/边界机制从未系统验证）。

v1.6 一句话：**把"连续性"补上——记忆连续（透明记忆中心）、对话连续（意图五态路由 + 细节打磨）、陪伴连续（有下文的主动关心 + 每周共同回顾）**。这层根基立住后，v1.7 的十项用户功能（时段仪式/提醒/阶段叙事/日记/人设工坊/群聊等）才有地基可盖。

## 1. 增量范围

### 1.1 P0（4 项——本期主体）

- **P0-1 透明记忆中心**：MemoryManager 数据全面透出——偏好 / 活跃话题 / 情绪记录三分区可视化，每条记忆带**来源与时间元数据**（自动提取 vs 手动添加，记忆可信度一目了然）；用户可查看 / 编辑 / 删除（删除即遗忘）。
- **P0-2 聊天意图五态**：用户消息路由五态（闲聊陪伴 / 技术提问 / 任务执行 / 日程待办 / 情绪倾诉）——首版纯规则识别，命中后走对应处理链；未识别落默认态（Q-B2 拍板）。这是后续所有"懂你"功能的路由骨架。

- **P0-4 聊天细节打磨**：分两类——**已实现待验证**（停止生效 / 上下文边界）与**需新做**（失败保留+重试 / 改后重发入口 / 反套话注入 / 发送状态显示）。

### 1.2 P1（3 项——目标内应交付）

- **P1-1 语音细节**：免提 / 语音输入链路打磨——失败反馈、退出恢复、打断体验、录音微提示。

## 4. P0 详细设计

### 4.1 P0-1 · 透明记忆中心

**用户故事**：作为主人，我想知道码铃到底"记住了我什么"、这些记忆是哪来的（她自己听出来的，还是我告诉她的）、是什么时候记的——记错了我能改，不想被记的我能删。**记忆可信、可控，我才敢让她一直陪着我。**

**现状确认（代码核实）**：
- `memory.py MemoryManager` 读写接口完整（list/set/delete_preference、get_active_topics、forget_topic、build_memory_context、build_topic_followup）。
- **缺口一**：记忆条目**无来源与时间元数据**（自动提取和手动写入不可区分，偏好连创建时间都没有）——"可信度呈现"需 memory.py 元数据扩展。
- **缺口二**：情绪记录只存单条 `habits.last_emotion / last_emotion_time`（memory.py:265-266），无历史。
- **缺口三**：话题只有 `forget_topic` 软删除（进 archived），无彻底删除。
- **缺口四**：`page_memories.py` 现状是**高光回忆册**（HighlightsManager），与 MemoryManager 无关——记忆中心需**新建页面**。

**交互草案（文字描述）**：
- 侧栏新增「记忆中心 📔」入口（置于「回忆 ✨」之下）；三分区：**主人偏好 / 活跃话题 / 情绪记录**。
- **可信度呈现（默认口径，Q-B1 拍板）**：每条记忆带两枚轻量角标——来源（「自动记下」= extract_from_dialogue 提取 /「你告诉我的」= 手动添加或对话中明示）+ 最近提及时间（"3 天前提到"）；无繁琐置信度数值（R-A：可信度靠来源透明建立，不打分）。
- **偏好区**：键值卡列表（内置键友好名映射：nickname→称呼、language→常用语言、code_style→代码风格），每条「✏️ 编辑」「🗑 删除」+「➕ 添加」。
- **话题区**：活跃话题卡（主题 + 来源 + 最近提及 + 状态），「✔ 标记完成」「🗑 彻底删除」；"已归档"折叠只读。
- **情绪记录区**：时间倒序（时间 + 情绪标签 + 触发消息摘要 ≤30 字），可单删；顶部中性说明："码铃从你的话里察觉的情绪，只在当下用来更好地陪你，绝不做统计。"（R-A/R-I 合规文案）。
- 底部固定一行：「📔 这里的一切只存于你的电脑，删除立即生效。」
- 红线自检：无条目计数徽章、无容量语义、无进度条。

**数据 / 接口依赖（memory.py 元数据扩展清单）**：
- 偏好条目升级 `{key, value, source, created_at, updated_at}`（source ∈ "auto" / "manual"）；旧数据 `{k: v}` 加载时自动迁移为 manual-source（来源标注"（早期记忆）"避免误标）。
- 话题条目增补 `source`；新增 `delete_topic_forever(subject)`（物理删除，archived 同步清除入口）。
- 新增 `emotions` 历史列表（`{time, emotion, excerpt}`，append 淘汰 >50 条）；`extract_from_dialogue` 命中情绪时 append。
- `build_memory_context()` 注入逻辑不变（仍读 preferences + active topics；删除当轮生效——重读断言）。

**验收标准**：
1. 三分区与 `user_memory.json` 实时一致；增删改立即原子落盘。
2. 删除任何条目后，当轮起 `build_memory_context()` 不再包含（删除即遗忘，自动化断言）。
3. 每条记忆显示来源与时间角标；旧数据迁移后不崩、来源标注诚实（"早期记忆"非伪造 auto）。
4. 情绪历史上限 50 自动淘汰；空态中性文案。
5. theme_color 全覆盖、深色模式正常、红线扫描零命中；高光册零回归。

**风险与工作量**：低。1.5–2 人日（memory.py 元数据扩展 0.5d + 新页 1–1.5d）。**优先级理由**：P0 之首——记忆是全部连续性功能（主动连续性 / 每周回顾 / v1.7 日记）的原料库，透明化是信任地基，且必须先行为其他项提供可观察的数据面。

### 4.2 P0-2 · 聊天意图五态

**用户故事**：作为主人，我同一句话既可能是随口聊天、可能是问技术、也可能是让她记个事——我希望她"听懂我说的是哪种事"，该聊的聊、该干的干、该记的记，而不是所有话都塞进同一条处理链。

**五态定义（PM 默认口径，Q-B2 拍板默认态）**：

| 态 | 含义 | 路由行为 |
|---|---|---|
| ① 闲聊陪伴（默认态） | 日常问候、随想、情绪轻交流 | 走既有普通聊天链（零变化） |
| ② 技术提问 | 代码 / 报错 / 技术概念 | 普通聊天链 + 既有联网搜索钩子（should_auto_search 判定收敛到此态） |
| ③ 任务执行 | 让她动手干活（读文件/修代码/跑测试） | 提示可开 Agent 模式（若已开 → AgentEngine 既有链） |
| ④ 日程待办 | "提醒我 / 别让我忘 / 帮我记着" | 写入 TodoManager（v1.6 仅记录 + 待办对话框可见；到点提醒触发链属 v1.7 F4） |
| ⑤ 情绪倾诉 | 明确低落表达（tired/anxious/lonely 强信号） | 识别打点 + 本轮回复语气放缓提示注入（轻量）；完整安慰模式 = v1.7 F6 |

**交互草案（文字描述）**：
- **识别口径：首版纯规则**（零 token、零延迟、离线可用）：意图词表 + 句式正则（"提醒我/叫我/别让我忘"→④；"帮我改/跑一下/看看这个报错/读一下"→③；"什么是/为什么/怎么做+技术词"→②；detect_emotion 强命中→⑤；其余→①）。词表做成可维护数据文件，社区可增补。
- **优先级**：用户**显式开关绝对优先**——Agent 开关亮着 → 用户消息一律走 Agent 链（跳过自动路由）；路由只作用于"无显式开关"的普通消息。
- **透明呈现**：路由命中非默认态时，气泡前小字提示一行（如"📭 已记入待办""🔧 检测到技术问题"），用户可感知她"听懂了哪类"；提示不入会话存档（与联网检索提示同款轻量模式）。
- **误路由兜底**：五态只改"附加行为"，**全部复用普通聊天链生成回复**（③也如此——Agent 关着时技术任务话照样回答，只是提示可开 Agent）——任何误判都不会导致消息"消失"或走丢，这是防失控的底设计。
- 红线自检：路由不产生任何数值、无"你今天问了 N 个技术问题"统计（R-A）。

**数据 / 接口依赖**：
- `gui/chat_service.py`：send_message 入口前置 `classify_intent(text) -> IntentType` 纯函数（新 `intent.py` 根级模块，纯 stdlib 可独立单测）；各态附加行为挂接（②联网钩子收敛、③Agent 提示、④TodoManager.add_item、⑤语气提示注入）。
- `memory.py detect_emotion`：⑤复用，零改动。
- chat_panel：小字提示渲染（复用联网提示样式）。

**验收标准**：
1. 词表用例集（≥40 句）五态判定准确率 ≥85%；未识别/低置信全部落默认态（不丢消息）。
2. Agent 开关显式开启时路由跳过、行为与 v1.5.2 完全一致（零回归）。
3. ④写入 TodoManager 立即可见（待办对话框）；⑤仅当轮注入、不入历史。
4. 路由纯规则零 LLM 调用零 token；意图词表数据文件可热加载。
5. 全链误判兜底：任何态下消息都得到回复（自动化断言"无消息黑洞"）。

**风险与工作量**：**中风险**（规则分类长尾误判——底设计"只附加不接管"已控风险上限）。1.5–2 人日。**优先级理由**：P0——五态是"懂你"的路由骨架：待办（v1.7 F4）、安慰模式（v1.7 F6）、技术链收敛全部挂它上面，本期不做、v1.7 处处重做。

### 4.3 P0-3 · 主动陪伴连续性

**用户故事**：作为主人，我希望她主动开口时带着"上次的内容"而不是空招呼；我也想告诉她"这句说到心坎了"或"这个别再提了"——**她的关心会因我的反馈越来越准**，这才是"我们"之间的连续。

**现状确认（代码核实）**：
- `memory.py build_topic_followup(min_hours, max_hours)` 已完整实现，**全树无调用方**。
- `proactive_scheduler.py` 四重闸 + 防自续命健康；`TodoManager.items()` 只读可用。
- **缺口**：主动消息发出后用户无任何反馈通道——话题续接永不学习"提腻了/提对了"。

**交互草案（文字描述）**：
- **内容拼装（优先级，同次最多 1 条，宁缺毋滥）**：①话题续接（build_topic_followup(1,72) 命中）②情绪延续（上次情绪 ∈ tired/anxious/lonely 且 24h 内 → "昨天感觉你有点累，今天好些了吗"）③待办轻提（未完成待办 ≥1 且 ≥24h 未动 → 不点名内容，"便签上还留着一件没做完的事，需要我帮你理理吗"）。无命中 → 完全回退现有模板（零内容也是体面）。
- **反馈三键（默认口径，位置 Q-B3 拍板）**：主动消息气泡尾部三个轻量小按钮——「💗 说到心坎」「🙈 先不提这个」「💬 想聊聊」：
  - 说到了心坎 → 该话题/内容源加权（续接间隔缩短至 48h，且这条话题在记忆中心标"她记对了"——与 P0-1 联动）。
  - 先不提这个 → 该话题**降权 14 天不再续接**（followup_muted_until 落盘），情绪延续与待办轻提同步静默 3 天。
  - 想聊聊 → 不改策略，仅引导"那我们接着聊"（正常聊天）。
  - 三键**只影响主动内容策略、绝不进亲密度计分链**（R-A）。
- 接线点：idle_hello 与启动问候两处（与 v1.7 F2 同口径）；同一话题提及后 `followup_asked_at` 7 天去重；`llm_enhance` 开关沿用（默认关、零 token）。
- 防自续命零回归：三键点击不是交互打点，不触发新一轮主动。

**数据 / 接口依赖**：
- `memory.py`：话题增补 `followup_asked_at` / `followup_muted_until` / `followup_score` 字段；新增 `record_followup_feedback(subject, feedback)`。
- `greeting.py`：新增 `build_contentful_line(memory_mgr, todo_mgr)` 独立函数（greeting 保持纯模板职责，拼装在调度侧）。
- `gui/proactive_scheduler.py` / `gui/main.py`：idle_hello / 启动问候接线；`ChatService.proactive_ask()` 既有独立投递路径复用。
- chat_panel：主动气泡（meta.proactive）尾部三键渲染 + 反馈信号回传。

**验收标准**：
1. 存在 1–72h 活跃话题时首次主动问候必含续接句；同话题 7 天去重；A9 四重闸完全同等生效。
2. 「先不提这个」后该话题 14 天静默（断言 muted_until）；「说到心坎」后间隔缩短（断言加权生效）。
3. 三键不触发 intimacy 加分（断言 score 不变）；不触发自续命。
4. 无内容源时输出与 v1.5.2 逐字一致（零回归）；llm_enhance=false 零 LLM 调用。
5. 三键位置在浮窗 / 主窗均可用；点击后按钮态收敛不重复提交。

**风险与工作量**：低。1.5–2 人日（含三键 UI）。**优先级理由**：P0——"主动"是码铃陪伴人设的核心承诺，但单向的主动只是"通知"；加上反馈闭环才成为"关系"。原料（build_topic_followup）现成，性价比全池最高之一。

### 4.4 P0-4 · 聊天细节打磨

**用户故事**：作为主人，我希望对话的每个"意外"都被温柔接住——网络断了消息还在、能一键重试；她说一半我喊停就真的停；她答不上的"你刚才说什么"会诚实说"长对话我精简过"，而不是编一个。

**现状核实与两类划分**：

| 细节项 | 现状判定 | 代码依据 |
|---|---|---|
| ① 停止生效 | **已实现待验证** | `stop_generation`（chat_service.py:720）+ cancel_check 协作中断 + 5s 线程等待（:731） |
| ② 上下文边界 | **已实现待验证** | `max_history_rounds` 截断（session.py:226）+ `auto_summary` 每 N 轮摘要注入前情提要（session.py:301-319） |
| ③ 编辑重发基础链 | **已实现待验证** | v10.2"就地截断+重发"（右键编辑回填→截断→重发），附确认框 |
| ④ 失败保留+重试 | **需新做** | `message_failed` 信号已有（诚实冒泡，chat_service.py:499 等），但失败后用户输入是否保留在输入框 / 会话、失败气泡无「重试」入口 |
| ⑤ 改后重发入口 | **需新做（收敛）** | 编辑链已存在（③），但**失败场景**无"编辑后重发"引导入口——失败气泡上无法直接修正重发 |
| ⑥ 反套话注入 | **需新做** | 上下文被截断/摘要后，对"你刚才说什么/你记得吗"类试探无防御——模型可能顺着幻觉编造 |
| ⑦ 发送状态显示 | **需新做** | 现状仅 thinking 表情联动；无"发送中 → 模型响应中 → 流式接收 → 重试中"的明确状态呈现 |

**交互草案（需新做部分）**：
- **④ 失败保留+重试**：API 失败 → 用户消息**保留在会话与 UI**（红色错误气泡附于其后），错误气泡上「🔄 重试」「✏️ 改后重发」两键；重试 = 原样重发该条（幂等，不重复入库——以消息 id 去重）；连续失败 3 次后提示检查网络/Key（引导文案走 user_messages 既有友好错误体系）。
- **⑤ 改后重发**：失败气泡「✏️ 改后重发」→ 回填输入框 + 该条之后内容截断（复用 v10.2 编辑链），用户改完即重发。
- **⑥ 反套话注入**：当上下文已触发摘要/截断（session 可查询标志），system 尾部注入诚实边界指令："较早期的对话已被精简为摘要；若主人问到已精简的内容，如实说明'那段我们聊天的细节我记不全了，只记得大概'，**绝不编造具体原话**"——与码铃"诚实产品底线"（v10.15 真实性修复包精神）一脉相承。
- **⑦ 状态显示**：聊天面板顶部一行细粒度状态（小字 chip）：发送中 → 模型响应中 → 流式接收（可并入现有 thinking 表情联动）→ 失败/重试中；状态切换不打扰、无进度百分比（R-A）。

**数据 / 接口依赖**：
- `gui/chat_service.py`：失败路径增补"保留用户消息 + 附错误气泡"结构；重试入口（同参重发）；system 组装链增补反套话指令块（条件注入：摘要发生过才注入）。
- `session.py`：暴露"上下文已精简"查询标志（auto_summary 触发后置位）。
- `gui/widgets/chat_panel.py`：状态 chip + 失败气泡按钮行；`user_messages.py` 友好文案复用。

**验收标准**：
1. **验证项**：①停止——流式中途停止后 3s 内 UI 恢复可输入、无残留线程（真机断言）；②边界——超 max_history_rounds 轮后请求 payload 长度受控、摘要自然衔接（payload 断言）；③编辑链零回归。
2. **新做项**：④断网场景消息不丢、重试成功后正常入库且不重复；⑤改后重发走通且旧内容截断干净；⑥摘要后问"我刚才说了什么"→ 回复含"记不全"类诚实表述、无编造（抽样评审 ≥5 用例）；未摘要场景不注入该指令（零打扰）。
3. ⑦状态流转与真实网络阶段一致，失败态可见；无任何数值/进度条（R-A）。
4. 全项深色模式 + 浮窗 + 主窗三环境一致。

**风险与工作量**：中（④⑤触碰发送链与 v10.2 截断语义，需谨慎；⑥依赖模型诚实度）。**2.5–4 人日**（验证三项 0.5–1d + 新做四项 2–3d）。**优先级理由**：P0——对话"意外时刻"的处理质量 = 用户对"她一直在线"的体感根基；且验证项是 R-K 发布诚实的直接标的（说"已实现"就要真验证）。

## 5. P1 详细设计

### 5.1 P1-1 · 语音细节

**用户故事**：作为主人，免提聊天是我的高频姿势——我希望识别失败时她告诉我"没听清"而不是无限沉默循环，退出免提后她的主动关心恢复得恰到好处。

**现状确认（代码核实）**：voice_input.py（STT 录音对话框 + 三态探测降级）、voice_conversation.py（免提状态机 idle→listening→recognizing→sending→speaking + 三通道退出 + 免提期 `set_busy("handsfree")` 暂停主动）、handsfree_bar.py（状态条）——机制完整，缺细节打磨与真机标定留档。

**四项打磨**：
1. **失败反馈**：免提循环中识别连续失败 ≥3 次 → 状态条明确提示"没听清，建议换个安静环境或改用打字"（现状为静默重试不打断循环，用户不知卡在哪）。
2. **退出恢复**：退出免提后主动陪伴恢复加 10 分钟静默缓冲（免提刚结束立即被主动问候打断体验差）；缓冲期计入 cooldown 而非独立闸。
3. **打断体验**：TTS 朗读中用户开口 → 立即停止朗读进识别（后开口打断已有，补打断时的话头截断处理与 toast 提示"我在听"）。
4. **录音微提示**：录音中状态条加音量呼吸动画/剩余时长提示（8 秒上限既有——纯 UI 反馈，无波形分析、不做音频落盘，R-B）。
- 另：真机音频全链路标定清单（灵敏度/噪音/打断阈值）随本项留档（此前 CHANGELOG 一直声明"真机标定"未落文档——R-K 文档诚实范畴）。

**依赖**：voice_conversation.py 状态机增补失败计数与缓冲逻辑；handsfree_bar.py UI；无新增依赖。
**验收**：连续失败提示出现且不打断退出通道；恢复缓冲 10 分钟内无主动开口（断言）；打断后"我在听"提示；全程无音频文件落盘。
**工作量**：1–1.5 人日（真机标定项另需本机环境）。**理由**：P1——语音是"她在身边"感最强的通道，机制已在、只差最后一层手感。

### 5.2 P1-2 · 陪伴质量测试套件

**用户故事**：作为维护者，我最怕"改一处问候逻辑，全站的温度都变了"——我需要一套剧本化测试，让每次改动后能自动验证"她还是那个她"。

**设计**：
- **剧本库**（`tests/companion_scenarios/`）：陪伴场景剧本 ≥15 条——时段问候（早/午/深夜）、话题续接（命中/去重/静默）、情绪延续、待办轻提、反馈三键三路径、升级播报恰一次、免打扰静默、意图五态路由用例、反套话诚实用例、记忆删除即遗忘等（覆盖 P0-1/P0-2/P0-3/P0-4 验收标准，测试与 PRD 验收逐条对应）。
- **双档执行**：**mock 档**（默认，进 CI）——LLM 调用全部 mock 固定响应，断言拼装逻辑/闸门/去重/字数；**真实档**（手动触发）——真实 LLM 跑剧本抽检"语气温度"（人工评审为主 + 关键词断言为辅），成本口径见 Q-B5。
- **温度护栏断言**：剧本内嵌红线断言（无数值词、无催促词、quiet 时段零输出）——把 R-A 扫描词检查从一次性 QA 固化为可重复执行的测试资产。

**依赖**：v1.4.8 既有 pytest/pytest-qt 体系（228 项）增量；陪伴域模块（greeting/proactive/memory/intent）已可独立单测（proactive_scheduler 无 Qt 可测的防御设计直接受益）。
**验收**：mock 档 CI 全绿且 <60s；真实档脚本可一键运行并输出逐剧本结果报告；R-A 扫描断言纳入。
**工作量**：1.5–2 人日。**理由**：P1——连续性功能全是"语气与时机"的软逻辑，没有回归护栏就敢改，等于裸奔。

### 5.3 P1-3 · 每周共同回顾

**用户故事**：作为主人，我想在每周日的傍晚收到一句"这就是我们的这一周"——她记下了我们一起做过的事、聊过的话题、我的高低起伏，像一张小小的周签，但不催不打卡。

**设计**：
- **生成时机**：每周日 18:00–21:00 窗口内**首次打开 app** 时生成并呈现（错过该窗口 → 本周不补发——"错过即错过"纪念日先例；Q-B4 拍板时间窗）。
- **内容骨架（规则汇总，默认零 LLM）**：本周消息数区间（用"忙碌的一周/清闲的一周"等档位词，不报具体数字——R-A）、新增话题与完成话题、高光回忆精选 ≤3 条（直接引用原文，用户自己收藏的）、情绪概览（"大部分时间都很有干劲"式档位描述）、相伴天数。**LLM 润色为可选开关**（默认关；开了 = 骨架喂 LLM 生成一段 80–150 字的"她口吻"周记，payload 只含骨架要点不含对话原文——R-I）。
- **呈现**：首页一张「本周回顾」卡片（点开全文）+ 记忆中心页可翻阅往期；**无系统通知、无推送**（打开才见，R-C 精神）。
- **存储**：`~/.maid_coder/weekly.json`（52 周滚动淘汰）；红线：无"连续回顾 N 周"、无周对比图表（R-A）。

**依赖**：highlights.py（周内高光查询——需补按时间范围过滤方法）、memory.py（话题/情绪周区间汇总）、companion.py（相伴天数既有）、page_home.py（卡片挂载）、page_memory_book.py（P0-1 页内往期 Tab）。
**验收**：同周仅生成一次（断言）；错过窗口不补发；默认档零 LLM 调用；卡片与翻阅页 theme_color 合规；52 周淘汰生效；红线扫描零命中。
**工作量**：1.5–2 人日。**理由**：P1 收尾——"每周"是连续性叙事的最长刻度，规则骨架版本成本极低、仪式感收益高；LLM 润色留给 v1.7 与日记共用预算口径。

## 8. 裁剪建议（分阶段）

1. **第一批（P0 核心）= P0-1 + P0-3**：记忆透出 + 主动连续性共享 memory.py 扩展，同一批开发联调效率最高；P0-3 的反馈三键依赖 P0-1 的记忆中心可观察，顺序上 1 先 3 后。
