## 0. 一句话背景

v2.4 把记忆**捕获链路**接通了，但这条链路上还有一批**正确性**问题（回放覆盖、无锁、常量漂移、路径随工作目录漂移）；本版把它们收口，并补上话题维度的最后一块能力缺口，同时把已被判定为"做不好"的内置酒馆正式标记弃用。

---

## 1. 版本目标与背景

### 1.1 为什么现在做这个

v2.4 修好了「记忆不积累」，紧接着暴露出三类遗留：

1. **正确性**：会话/崩溃恢复会用旧快照覆盖全局记忆（数据回退）；MemoryManager 无锁而写入频率已上升；`config.yaml` 路径随工作目录漂移（历史上出过事故）。
2. **能力缺口**：话题只有静态 top-3 注入位，归档后即失联；无完成检测；提取词表写死在代码里，扩充要改代码。
3. **维护性**：死代码与常量漂移（定义了不用的常量、两份重复的关系预设、硬编码天数）。

### 1.2 用户已拍板的三条（**不再抛回**）

| # | 决策 | 落点 |
|---|---|---|
| P1 | 「一、二全部能修的修」 | §2.1 / §2.2 |
| P2 | 「三、四可以加」 | §2.3 |
| P3 | 「酒馆功能太差，逐步去掉，不再优化」 | §4 N1；T-20 记忆钩子**取消** |
| P4 | GitHub 公告措辞改为「上线了开源项目 Silly Tavern」 | 待用户确认具体文案（§3 Q-V25-4） |

### 1.3 现状事实基线（逐条实测）

见 `docs/design-v25.md` §1.3（F1–F12）。其中两条需要特别提示：

- **F10：`config.yaml` 有 7 处（共 10 个调用点）裸相对路径解析** —— 这就是那个"从不同工作目录启动会读写不同配置"的根因。
- **F12：`docs/audit-功能真实性清单-2026-09-07.md` 关于 C1 知识库 / C2 待办的结论已过时**（该审计称二者"GUI 零引用"，实际 GUI 已接线）。**按它办事会做无用功。**

| # | 不做 | 理由 |

| N1 | **不再优化内置酒馆** | 用户判定「功能太差，逐步去掉」（P3）。本版起只修不增；`design-v22.md:1215` 的 T-20 记忆钩子随之取消 |

| N8 | 不机械替换裸 `print` | 清点后集中在**依赖缺失引导路径**（日志系统尚未初始化，`print` 是唯一用户通道），保留是正确决策 |
