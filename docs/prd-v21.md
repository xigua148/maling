## 0. 一句话背景

v2.0 刚把「自动更新与分发」交付——从此**装过一次码铃的人能自动拿到新版本**，界面投资会随存量用户放大。但界面本身还停在 v1.9「视觉重塑」的**静态完成态**：四风格 QSS 已全站落地、六字体系统已随包、强调色派生与深浅模式已就绪，**但全树零动效（无一处 `QPropertyAnimation`）、零毛玻璃（无 Mica / Acrylic / DWM 调用）、图标仍是 emoji/unicode 文本（侧栏 `NAV_ITEMS` 用 `\U0001F4AC` 这类字形当图标）、深色模式仅做到"能用"未做到"精致"**。用户已备好整套 UI 设计工具与参考素材，明确要求把界面推进到"现代、精致、有动效"。

v2.1 一句话：**不换骨架，只上妆与加戏——在既有的四风格 × 六字体 × 强调色底盘上，做一轮 QSS 精细打磨 + 克制的动效 + Windows 原生毛玻璃 + 统一的矢量图标 + 暗色模式精修，并且每一样效果都能被用户一键关掉。**

| 效果 | 第三方方案（触碰 R-F） | **零依赖替代（推荐）** | 技术可行性 |
|---|---|---|---|
| 动效 | 无（qtawesome 的 Spin/Pulse 仅图标动画） | **PySide6 内置** `QPropertyAnimation` / `QParallelAnimationGroup` / `QEasingCurve`（40+ 缓动） | 已确认 `PySide6` 为既有必需依赖（`requirements_gui.txt`），`gui/qt_compat.py` 集中导入，扩展即可 |

## 7. 约束与风险

### 7.1 性能（R-P）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 动效拖累主线程 | Qt 动效在 GUI 线程执行，频繁动效可能掉帧 | 时长 ≤ 220ms、克制效果、M-0 单点收口、提供总开关（M-6）、避免在滚动/重载时批量播放（M-2 验收②） |
| 毛玻璃开销 | DWM 材质在部分显卡/远程桌面下开销大或不可用 | G-0 能力探测 + G-3 自动降级 + 开关；远程桌面/不支持环境纯色 |
| 图标字体渲染 | 字形渲染 vs 图片缓存 | 图标字体单文件、按需着色；必要时缓存 `QIcon`（`QPixmapCache`） |
| 粒子/渐变叠加 | D 风格浅海渐变 + 毛玻璃叠加可能加重绘制 | 渐变走 QSS `qlineargradient`（轻量）；避免多重半透明叠加 |

### 7.2 兼容性

| 维度 | 约束 |
|---|---|
| Windows 版本 | Mica 需 Win11 22H2+；Acrylic 需 Win10 1809+；更旧系统纯色降级（G-0） |
| 深色模式 | 四风格 × 浅深两维组合回归；C 风格 `dark_locked` 强制深色行为不变（`apply_night_lock`） |
| DPI / 缩放 | 矢量图标天然支持高 DPI 缩放（优于 emoji 文本）；毛玻璃在不同缩放下的边界复核 |
| 远程桌面 / 虚拟机 | DWM 材质不可用 → 必须有纯色降级路径，不得黑窗 |
| 与透明度滑杆 | F-9 透明度滑杆（`setWindowOpacity`）与毛玻璃叠加冲突 → Q-V8 |

### 7.3 可回退性（R-Q）

- **每一个新效果都必须是可关闭的**：动效（M-6 三档：关/柔和/标准）、毛玻璃（G-3 开关）。
- **环境不支持时自动降级而非报错**：毛玻璃不可用静默纯色（G-1）。
- **旧存档零迁移**：新配置键缺失时取类默认（沿用 `GuiConfig.load` 的 `hasattr` 范式，`config.py:121`）。
- **四风格可回退到 v1.9 现状**：精修若引入回归，可按风格单独回滚 QSS 文件（四文件独立）。
- **不改变既有契约**：`theme_changed(str)` 签名、`load_theme` 变量替换、`_active_palette`、`derive_accent_palette`、`set_theme_mode` 语义零变更（R-D）。

### 7.4 最大风险

| # | 风险 | 定级 | 说明 |
|---|---|---|---|
| R1 | **R-F 冲突未决**（Q-V1） | **高** | 若用户拍板"放宽红线"引入 qtawesome/QStyleHelper，则需连带评估打包一致性、更新链可复现性、体积；若走零依赖替代，则毛玻璃/图标的实现复杂度上升到架构级（`ctypes` DWM 封装需真机验证）。**这是本轮唯一的方向性风险** |
| R2 | **毛玻璃真机兼容**（G-1/G-2） | 中高 | Mica/Acrylic 在非 Win11、远程桌面、多显示器、高 DPI 下表现不一；mock 测不出，必须真机验证 |
| R3 | **动效与交互手感** | 中 | 动效过强显廉价、过弱无感知；需真机调参 + 用户主观确认 |
| R4 | **Qt QSS 无 transition 的认知陷阱** | 中 | 实施者若误以为 QSS 能做过渡，会走弯路；已在 §2.2 技术前提明确 |
| R5 | **四风格 × 浅深 × 效果组合爆炸** | 中 | 4 风格 × 2 深浅 × (动效开/关) × (毛玻璃开/关) 组合回归量大，需矩阵化抽样 |

### 9.3 PM 对最大风险的主张（供架构细化）

1. **R-F 是本轮唯一的方向性风险，必须先裁决再动手（Q-V1）。** 我的主张是**不放宽红线**：本轮目的是"把界面从能用推进到精致"，而三条零依赖路径（内置动画 / ctypes DWM / 图标字体）技术上完备且与项目既有范式（`winreg` 封装、字体随包）一致；为锦上添花的 UI 效果破坏贯穿多轮的打包红线，性价比不成立。**若用户坚持用 qtawesome/QStyleHelper，则须单独立项评估其对 v2.0 更新链可复现性的影响，不能"顺手引入"。**
2. **毛玻璃必须"能力探测 + 自动降级 + 可关"三件套**（G-0/G-1/G-3），否则在非 Win11 / 远程桌面场景会直接变成"软件坏了"。真机验证是硬要求，mock 测不出 DWM 行为。
3. **动效"克制"是产品判断而非技术判断**：Qt QSS 无法做 transition（§2.2），所有动效走代码侧，正因如此更要定死"时长 ≤ 220ms + 总开关 + 强度档"，避免变成廉价特效堆砌。
4. **四风格的可回退性**：S 组精修按风格粒度独立（四个 QSS 文件独立），任一风格出问题可单独回滚，不影响其余三风格与 v1.9 既有色值。
