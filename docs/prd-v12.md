## 0. 一句话背景

v1.1.0 码铃完成了「Agent 能力从 0 到 1」：8 种工具、授权弹窗、轨迹卡片，女仆能自己动手干活了。
但当前产品给人的第一印象仍是「一个带女仆口吻的 AI 编程工具」——**用户没有理由每天打开它**。

v1.2 的任务是**换重心**：码铃首先是一位「住在桌面里的 AI 女仆伙伴」，让用户每天想打开、愿意玩、愿意托付事情给她；自主干活（C1–C4）继续补齐，但它是「能力背书」，为陪伴关系提供信任与成就感，而不是产品唯一的门面。

## 1. 产品定位、目标用户与差异

**定位一句话**
码铃是「住在桌面里的女仆 AI 伙伴」——她先陪你，再帮你干活；陪伴带来每天想打开的引力，自主任务带来「我家女仆真能干」的骄傲。

**目标用户**
长时间对着电脑的开发者与知识工作者（尤其独立开发者、编程学习者、单人工作场景），他们想要一个「在场、有情绪、记得住我」的工作陪伴者，而不只是一个用完即走的效率工具。

**与竞品的差异（一句）**
Cursor / Cline / Continue 等编程助手解决「问题本身」，码铃解决「谁陪着你把问题解决掉」——别人是工具，她是一个有成长线的角色；干活能力是让这个角色「可信、可骄傲」的支撑，而非卖点本身。

## 2. 核心体验故事（用户故事）

**US-1　早上的第一声招呼（日常陪伴 · 打开引力）**
清晨打开码铃，首页（房间）里女仆小姐已经精神饱满地站着，用与好感度匹配的语气说「主人早~ 昨晚睡得好吗？」——并附上一条「每日动态」（今天是相伴第 N 天、有什么待办提醒、随口一句关心）。用户没开口，先被认真对待了。→ 每天打开的动力。

**US-2　她一直在窗口角落（日常陪伴 · 在场感）**
主窗角落常驻着一枚小码铃（约 48–72px），离开一阵回来，发现她在「安静等待 / 偷偷犯困 / 见到你开心」的表情之间切换。点一下她：铃铛轻响、递茶式的小互动 + 一句贴心情话，好感度悄悄涨一点。用户在窗口角落感知到一个「一直陪着、属于我的」存在——不用特意打开某个页面，她就在那儿。

**US-3　托付小任务（自主干活 · 可信）**
「帮我把 `tests/test_utils.py` 跑一下，挂了帮我修」。码铃开启 Agent 模式：先亮出 2 步小计划，在项目白名单内跑 pytest、看到失败输出、自己改一行、再跑一遍直到通过——轨迹卡片一步步点亮，全程授权清晰、可随时叫停。通过后她带着任务结果回来，骄傲地等一句夸奖。→ 干活能力变成「被信任的陪伴者」的证据。

**US-4　托付大任务（自主干活 · 可靠）**
「这个模块的搜索功能帮我重构一下」。码铃先给出一份拆解后的步骤清单，逐项执行，中途随时可以问她「做到哪了」，她能基于任务级记忆（目标+已完成+当前卡点）汇报进度，而不是失忆重来。用户安心地把「半个下午的工作」交出去。

**US-5　时间带来的关系感（成长线 · 无压力）**
一周、一月过去：陪伴足迹页里躺着相伴总天数、首次相见日、一起完成过的任务；成就徽章悄悄点亮「初次托付」「连续 3 天见面」「渐渐亲近」。没有分数条、没有打卡压力——关系用称谓和回忆自然呈现，用户感受到的是「一路走来」，而不是「没达标」。

**US-6　她先开口，但从不多嘴（主动陪伴 · 有节制）**
你忙了一小时没理她，她只在托盘里轻轻冒一句「主人还在忙呀，码铃安静陪着你~」；深夜或免打扰时段绝不出现。想知道她说了什么，点开独立聊天浮窗就能看到。→ 主动，但克制；被惦记，但不被打扰。

## 4. 需求池

优先级口径：
- **P0** = v1.2 必须交付，缺一项则「陪伴优先 + C1–C4 完成」不成立；

## 8. v1.2 明确不做（Non-goals）

- **不做开源发布**：不上 GitHub Release、不做社区/issue、不排开源节奏；`version.json` 的占位发布地址维持现状。
- **不做重动画/重表现引擎**：无骨骼动画、Live2D、SPINE、3D、粒子特效、帧动画逐帧序列；v1.2 的「活」全部来自 静态表情切换 + 轻量 QSS 动效。
- **不做账号/云同步/移动端/远程访问**：陪伴数据纯本地（`~/.maid_coder/`）。
- **run_command 不是通用终端**：不开放任意 shell 命令、不是终端模拟器；C1 仅白名单内运行与回读，安全边界优先于能力上限。
- **不做无监督的自愈循环**：C2 内层迭代最多 N 轮、可中止、写文件仍走授权；绝不「无限重试/越权修改/不告知即改代码」。
- **主动陪伴只做「有节制版」（A9），不做打扰式推送**：码铃仅在应用运行时、免打扰时段之外、频控与单日上限内主动开口；不做 24h 后台常驻主动说话、不做系统级定时弹窗/闹钟、不做基于行为分析的推送（A9 边界为 P0 级设计约束，非后补）。
- **不做「监督/评判式陪伴」**：摄像头与麦克风不做对用户的学习监督、专注度评分、内容分析或任何「AI 管人」形态；v1.2 连「在场感知」增强都不做（专注陪伴 MVP 属 P2 观察项，需单独隐私评审）。
- **不做数值养成焦虑（心情/好感）**：UI 不展示心情值/心情条/经验条/分数/打卡倒计时；心情与好感永不 gate 功能、永不作负向反馈（A1/A2/A5 红线）。
- **不做 Flowise/Dify 式 node 工作流编辑器**：v1.2 不引入节点图编辑前端与图形数据模型；任务步骤的可视化仅限 C3-2 只读进度视图；「可视化编排」列 P2 观察，不构成 v1.2 承诺。
- **A8-ext 脱窗悬浮窗不进 v1.2**：v1.2 只做「窗口内角落常驻宠物」（A8）；脱离主窗的桌面贴边小窗是 P2 扩展位，仅预留资产与状态源兼容口，不做形态承诺。
- **UI 简洁化不做成「换皮成通用工具」**：B8 收敛的是噪音与杂乱，码铃粉白基调/圆角语言/铃铛意象/情感化微动效是辨识度红线，不允许在「简洁」名义下被抹成中性工具风。
- **不做大范围框架重构**：不改 GUI 三栏主窗骨架、不重构聊天会话/消息数据模型、不引入新的大型第三方 UI/图形依赖（除非极小且必要并先过架构评审）。
- **不做多语言/国际化、不做无障碍专项**（跟随既有，不新增承诺）。
- **不承诺表情动画帧率/流畅度指标**（受 Qt + 无专用渲染投入约束）。
